# docs/ — mobile-viewable POC frontends

This folder is the GitHub Pages publishing root for the whole repo (see
`GITHUB_PAGES_SETUP.md` at the repo root for the one-time GitHub setup).
Everything under here is served as-is at
`https://espenhk.github.io/espenhk-hobby-projects/`.

## Convention

Each project that wants a mobile-viewable POC gets its own folder here,
named after the project:

```
docs/
├── index.html              # landing page linking to each project below
├── football-scheduler/
│   └── index.html          # published at .../football-scheduler/
└── <new-project>/
    └── index.html          # published at .../<new-project>/
```

Whatever's in `docs/<project>/index.html` is what phones (and everyone
else) see — nothing outside `docs/` is served, so a project's real source
lives in its own top-level folder as usual, and only the built/rendered
output for viewing gets copied or generated into `docs/<project>/`.

## Two ways to fill a project's folder

**A. Pre-rendered static HTML (what `football-scheduler` does).** If a
project can already render itself to a single self-contained HTML file
(inline CSS/JS, no external assets), just publish that file as
`docs/<project>/index.html`. `football-scheduler/scripts/publish_web.py`
is the pattern: it runs the project's normal report generator and copies
the result into `docs/football-scheduler/index.html`. Cheapest option —
no new frontend code at all.

**B. Hand-written vanilla JS/HTML/CSS.** For a project with nothing to
render ahead of time (interactive, needs live input), ask Claude to build
a small app directly under `docs/<project>/`:

- Plain HTML/CSS/JS — **no build step, no npm, no bundler.**
- Any third-party library loaded from a CDN (`<script src="https://...">`),
  not installed as a package.
- Multiple files are fine (`index.html`, `styles.css`, `app.js`) — you're
  only skipping the toolchain, not forced into one file.
- If it needs data, either fetch a JSON file committed alongside it
  (generated by the project's normal Python code, same idea as option A)
  or call a public API directly from the browser.

A good prompt for a fresh POC:

> Build a simple mobile-friendly frontend for `<project>` under
> `docs/<project>/`. Vanilla JS, no build step, load any dependencies from
> a CDN. `index.html`, `styles.css`, `app.js` is fine as separate files.

## Publishing a change

1. Work on a branch (Claude Code — mobile or desktop — creates one
   automatically for a task started against this repo).
2. Regenerate or hand-edit the project's `docs/<project>/` output and
   commit it.
3. Open/merge the PR. GitHub Pages always serves the `main` branch, so the
   live URL updates automatically once the merge lands — no separate
   deploy step.

To preview a branch before merging, see the "previewing before merging"
note in `GITHUB_PAGES_SETUP.md`.
